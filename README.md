# GadgetStore CRM

Вебсистема для обліку товарів магазину мобільних пристроїв і гаджетів. Допомагає вести каталог і залишки, оформлювати продажі, знаходити чеки та переглядати коротку аналітику продажів.

## Можливості

- Дашборд із загальною вартістю залишків, виручкою, прибутком, товарами з малим залишком і найпопулярнішими товарами.
- Каталог товарів: пошук, категорії, бренди, артикул, ціни, залишок, гарантія та фото.
- Каса з пошуком товару, перевіркою доступної кількості та автоматичним зменшенням залишку.
- Історія продажів із фільтром за назвою товару, датою та номером продажу; чек відкривається в новій вкладці.
- Керування категоріями, брендами та обліковими записами менеджерів.
- Український та англійський інтерфейси, адаптивна верстка.
- Авторизація адміністратора і менеджерів; паролі зберігаються у вигляді PBKDF2-SHA256-хешів.

## Технології

- Go та стандартний `net/http`.
- PostgreSQL (`github.com/lib/pq`).
- HTML-шаблони у `templates/`.
- Docker для розгортання.

## Запуск локально

Потрібні Go 1.26.1+ і PostgreSQL. Стандартні локальні параметри бази: `127.0.0.1:5433`, користувач `postgres`, база `gadget_store_db`. Їх можна перевизначити змінними `DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD`, `DB_NAME`.

```powershell
go test ./...
$env:APP_PORT = "8080"
go run .
```

Відкрийте <http://localhost:8080>. Для локальної бази початкові облікові дані: `admin` / `admin123` і `manager` / `manager123`. Змініть їх перед використанням із реальними даними. Таблиці створюються та оновлюються під час запуску застосунку.

Замість набору змінних `DB_*` можна вказати повний рядок підключення `DATABASE_URL`. Для керованої хмарної бази використовуйте рядок із TLS, наприклад із параметром `sslmode=require`.

## Безкоштовне розгортання: Render + Supabase

Файли `Dockerfile` та `render.yaml` налаштовують вебсервіс Render. PostgreSQL і сховище фотографій працюють у Supabase. Це дозволяє залишатися доступним за HTTPS-посиланням з різних пристроїв і мереж та не втрачати фото після перезапуску контейнера.

### 1. Створіть проєкт Supabase

1. Створіть проєкт у [Supabase](https://supabase.com/dashboard) і збережіть пароль бази даних у менеджері паролів.
2. У налаштуваннях підключення скопіюйте PostgreSQL connection string. Для Render використайте рекомендований Supabase рядок Session pooler, якщо пряме підключення недоступне; рядок має включати SSL (`sslmode=require`). Він стане значенням `DATABASE_URL`.
3. У **Storage** створіть bucket `product-images` і зробіть його публічним для читання зображень. Завантаження та видалення фото виконує тільки серверний Go-застосунок.
4. Скопіюйте Project URL і `service_role` secret з налаштувань API. `service_role` обходить правила доступу Supabase, тому зберігайте його лише як серверний секрет Render. Ніколи не додавайте його в репозиторій, README чи браузерний JavaScript.

Безкоштовний тариф Supabase має обмежений обсяг і може призупинити проєкт після періоду низької активності. Перевіряйте чинні ліміти й регулярно експортуйте важливу базу даних.

### 2. Підготуйте GitHub

Завантажте цей репозиторій у GitHub. У ньому мають бути `Dockerfile`, `render.yaml`, папка `templates/` і початкові файли `uploads/`. Файл `.gitignore` виключає IDE-налаштування та `.env`.

### 3. Створіть сервіс Render

1. У [Render Dashboard](https://dashboard.render.com/) оберіть **New → Blueprint** і під’єднайте репозиторій `GadgetStore-CRM`.
2. Перевірте план `Free` та сервіс `gadget-store-crm`.
3. Під час створення Blueprint заповніть секретні змінні:
   - `DATABASE_URL` — рядок підключення PostgreSQL із Supabase;
   - `ADMIN_PASSWORD` — унікальний пароль адміністратора довжиною щонайменше 12 символів;
   - `MANAGER_PASSWORD` — окремий унікальний пароль менеджера довжиною щонайменше 12 символів;
   - `SUPABASE_URL` — Project URL;
   - `SUPABASE_SERVICE_ROLE_KEY` — серверний `service_role` secret.
4. Дочекайтеся статусу **Live** та відкрийте адресу `https://gadget-store-crm.onrender.com` (Render покаже фактичну адресу сервісу).
5. Увійдіть як `admin` або `manager` із паролем, який ви задали у Render. Менеджер має касу й робочі сторінки; керування користувачами обмежене адміністратором.

Render Free може присипляти сервіс після простою, тому перший запит після паузи відкривається із затримкою. Вміст файлової системи контейнера не є постійним: нові фото зберігаються у Supabase Storage. Не використовуйте локальне сховище Render для робочих даних.

### Наявні дані

Розгортання створює таблиці в новій базі, але не переносить дані з локальної PostgreSQL автоматично. Перед реальним запуском експортуйте локальну базу, імпортуйте її в Supabase та переконайтеся, що посилання на наявні зображення доступні з хмари. Для імпорту бази з уже створеними користувачами Render-паролі для початкового створення не замінюють наявні паролі в таблиці `users`.

## Змінні середовища

| Змінна | Призначення |
| --- | --- |
| `DATABASE_URL` | Повний рядок підключення PostgreSQL; має пріоритет над `DB_*`. |
| `DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD`, `DB_NAME` | Локальні параметри PostgreSQL. |
| `PORT` | Порт, який задає платформа хостингу; має пріоритет над `APP_PORT`. |
| `APP_ENV` | Значення `production` вмикає обов’язкові сильні початкові паролі та Secure cookie. |
| `ADMIN_USERNAME`, `ADMIN_PASSWORD` | Початковий обліковий запис адміністратора (створюється, якщо такого логіна ще немає). |
| `MANAGER_USERNAME`, `MANAGER_PASSWORD` | Початковий обліковий запис менеджера (створюється, якщо такого логіна ще немає). |
| `SUPABASE_URL` | Адреса проєкту Supabase. |
| `SUPABASE_SERVICE_ROLE_KEY` | Серверний секрет для операцій із фото. |
| `SUPABASE_STORAGE_BUCKET` | Назва публічного bucket для фото; за замовчуванням `product-images`. |

Шаблон локальних змінних лежить у `.env.example`. Застосунок сам його не завантажує: задайте змінні у своєму середовищі або додайте локальний `.env` через інструмент запуску, не комітьте його.

## Структура

```text
.
├── db.go                 # PostgreSQL, міграції та облікові записи
├── handlers.go           # HTTP-обробники, валідація та фото
├── main.go               # маршрути й запуск сервера
├── templates/            # сторінки HTML
├── uploads/              # початкові локальні зображення товарів
├── Dockerfile            # контейнер для хостингу
├── render.yaml           # Render Blueprint
└── handlers_test.go      # автоматизовані тести
```
